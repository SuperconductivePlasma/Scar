# Feasibility of the N = 9 exact diagonalization in a Claude Code cloud container

Measured on this container, 2026-09-23. All numbers below are either computed
exactly (dimensions) or benchmarked on this machine (timings, memory), not
guessed.

## Verdict

| Size | CM-free dim | Status here |
|------|------------|-------------|
| N=6  | 149        | trivial (< 1 s) |
| N=7  | 843        | trivial (< 1 s) |
| N=8  | 5,200      | comfortable (minutes, < 3 GB) |
| N=9  | **33,517** | **not feasible in this container** |

N=9 is blocked by two independent resource walls, one of which (the
center-of-mass projection) is easy to overlook when scoping the job.

## Machine actually available

```
CPU        4 cores, AVX-512; OpenBLAS 0.3.31 -> 230 GFLOP/s dgemm (measured)
RAM        15 GiB total.  MEASURED: one 33,517^2 float64 array (8.39 GiB)
           allocates fine; a second one is OOM-killed.
Disk       ~30 GB writable (verified by writing a 10.7 GB file)
Session    ephemeral container, reclaimed after inactivity
```

## Hilbert space dimensions (exact)

`q = M - N(N-1)/2`; full dim = [x^q] prod_{j=1..N} (1-x^j)^-1, CM-free uses
j = 2..N. Reproduces the prompt's expected 149 / 843 / 5200.

| N | M | q | full det. dim | CM-free dim |
|---|---|---|---|---|
| 6 | 45 | 30 | 1,206 | 149 |
| 7 | 63 | 42 | 8,033 | 843 |
| 8 | 84 | 56 | 55,974 | 5,200 |
| 9 | 108 | 72 | 403,016 | **33,517** |

Consistency check of the CM tower: 403,016 - 369,499 = 33,517, i.e.
dim ker(b) at M equals D_full(M) - D_full(M-1), as it must for the Heisenberg
tower generated by b = sum_i d/dz_i, [b, b†] = N.

## Wall 1 — the dense eigensolve (borderline, custom code only)

Dense H in the CM-free block: 33,517^2 x 8 B = **8.99 GB (8.37 GiB)**. It fits
in RAM, but the standard calls do not:

| call | peak RSS (measured multiple of n^2*8B) | at D=33,517 | fits 15 GiB? |
|------|------|------|------|
| `numpy.linalg.eigh` (values+vectors) | 5.08-5.19x | ~46 GB | no, OOM-killed |
| `numpy.linalg.eigvalsh` | 2.03-2.13x | ~18 GB | no, OOM-killed |
| `scipy.linalg.eigh(overwrite_a=True, eigvals_only=True)` | ~1.05x | ~9.4 GB | yes |

Measured timings (4 threads):

| n | eigenvalues | + eigenvectors | peak RSS (vec) |
|---|---|---|---|
| 6,000 | 6.2 s | 15.9 s | 1.39 GiB |
| 10,000 | 31.1 s | 60.0 s | 3.78 GiB |
| 14,000 | 130.5 s | 175.7 s | 7.37 GiB |

Extrapolated to D = 33,517 (the eigenvector path scales ~n^3.2, the
eigenvalue path steepens to ~n^4.3 between the last two points, so its range
is wider):

- eigenvalues only: **~0.5-1.5 h**
- eigenvalues + all eigenvectors: **~40 min** for the fused `dsyevd` if memory
  allowed — it does not, so in practice **~1-2 h** via hand-rolled LAPACK
  (`dsytrd` -> `dstemr`/`dstein` in index chunks -> `dormtr` back-transform,
  streaming to a memmap). Peak ~10 GiB. This is not a scipy one-liner.
- eigenvector output on disk: 8.99 GB of the ~30 GB budget.

float32 would halve the memory but eigenvalue error (~1e-5 of the bandwidth)
would exceed the mean level spacing (~3e-5 of the bandwidth at D = 33,517),
destroying exactly the mid-spectrum statistics sections 6-7 depend on. Not an
option.

## Wall 2 — the CM-free basis (the actual blocker)

Q4 is evaluated through orbital occupations `<n_b>`, which are diagonal *only*
in the Slater-determinant basis. So the CM-free eigenvectors have to be
expressible in the 403,016-dimensional determinant space.

An explicit orthonormal CM-free basis is a dense

    403,016 x 33,517 x 8 B = 108 GB

matrix — more than 3x the entire disk and 7x the RAM. These vectors really are
dense (the Laughlin state itself is one of them). The N=8 analogue is only
55,974 x 5,200 x 8 B = 2.33 GB, which is exactly why N<=8 is easy and N=9 is
not: a 46x jump in this object.

The best workaround avoids storing it, by projecting pivot determinants with
the normal-ordered CM-vacuum projector P0 = sum_k (-1)^k (b†)^k b^k / k! and
reading off only the pivot components:

    S_ab = <d_a| P0 |d_b>,    H_ab = <d_a| H P0 |d_b>   (H commutes with P0)

then solving the generalized problem H c = E S c. Priced with measured numbers
on this box:

- H in the full determinant basis: 236 off-diagonal connections per row
  (sampled) -> nnz ~ 9.5e7, CSR ~1.14 GB. Fine.
- Sparse SpMM throughput here: **1.86 GFLOP/s** (memory-bound).
- Projecting all 33,517 pivots (Horner nesting, ~2q=144 ladder applications
  each): **~5 h**. Applying H to the projected vectors: **~1 h**.
- Then S and H are 9 GB *each*: 18 GB cannot coexist in RAM (measured: second
  allocation is OOM-killed), and S + H + eigenvectors = 27 GB of a 30 GB disk,
  with no margin for checkpoints, the audit reruns, or the N<=8 archives.
- S is the Gram matrix of non-orthogonal projected determinants; its condition
  number is plausibly 1e10-1e20, which corrupts precisely the mid-spectrum
  eigenvalue differences the ETH and level-statistics analysis needs.

## What N = 9 would actually need

~64-128 GB RAM, ~200-500 GB scratch, 8-32 cores, roughly a day of compute with
expert out-of-core code — i.e. a cluster node, which the prompt already
anticipates ("If local resources are insufficient, prepare a reproducible
cluster workflow").

## The physics spec itself checks out

Verified independently before costing it, so the obstacle is purely resources:

- `V_m = g2/(4 m lB^2)` reproduced by direct integration of `<1/r^2>` in the
  relative LLL channel for m = 1,3,5,7,9.
- `<sum_i r_i^2> = N(3N-1) lB^2` follows from `sum_b (2b+2) <n_b>` with
  `M = 3N(N-1)/2`.
- `Q4/lB^4 = 4 sum_b (b+1)(b+2) <n_b> = 4<sum_i b_i^2> + 12M + 8N` is
  self-consistent.

## Recommendation for the prompt

1. Make N = 6, 7, 8 the deliverable that must actually run, and state
   explicitly that N = 9 is to be *prepared and validated* (basis construction,
   dimension check against 33,517, memory/time budget, submission scripts) but
   **not executed** in the container.
2. Tell the agent up front about the two walls, otherwise it will spend hours
   discovering the OOM by trial and error — the naive `numpy.linalg.eigh` path
   dies only after the matrix is built.
3. Note the statistics consequence: without N = 9 only three sizes remain
   (149 / 843 / 5200). The prompt already says four sizes cannot establish
   strong ETH; three is weaker still, and 149 is too small for the central-half
   windowing in section 6.
4. If N = 9 spectra are essential and a cluster is not, the standard escape is
   a compact geometry (torus: magnetic translations block-diagonalize cheaply;
   sphere: no CM problem at all) — but that changes the stated physics of the
   infinite plane, so it is a different study, not a shortcut.
